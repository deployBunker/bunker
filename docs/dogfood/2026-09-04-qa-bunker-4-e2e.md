# QA-BUNKER-4 — Port-range allocator leak fix: live E2E evidence

Date: 2026-09-04 · Commit under test: b4c3c483e086075140cca4885cea0fe3c862dfb8 · Host: bunker-mvp (78.46.173.180)

## Task

Non-force destroy returned `not_found` after userdel failure WITHOUT freeing the port range
(internal/agent/manager_destroy.go Step 3 early return). Proven live on bunker-las-03:
19 ok spawns vs 9 ok destroys + 15 not_found destroys → 10 leaked ranges = entire pool
(`pool exhausted: 10 ranges`), 48 orphan users with running rootless dockerd.

## Fix (commit b4c3c48)

1. Unconditional idempotent `m.portAlloc.Free(agentID)` in the not_found early-return path
   (Free no-ops for unknown IDs; spawn already had the Free-on-failure precedent).
2. Hardening: `waitAgentProcessesExit()` polls up to ~10s after dockerd stop/disable for the
   agent user's rootlesskit/dockerd PIDs to exit, SIGKILLing stragglers, before `userdel -rf`
   — keeps destroys out of the not_found path in the first place (the TTL reaper is the
   frequent triggering caller).
