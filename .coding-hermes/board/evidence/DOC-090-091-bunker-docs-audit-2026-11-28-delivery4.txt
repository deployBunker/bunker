Manage API keys and the JWT signing secret on a bunkerd server.

key rotate  Rotate the HS256 JWT SIGNING SECRET (NOT a bearer token) without
            downtime. The new secret is printed EXACTLY ONCE — store it
            (env-file / auth.jwt_secret_file) before you lose this output.
            The switch is IMMEDIATE: new-secret tokens validate with NO
            restart; persisting it and restarting the daemon is only
            crash-persistence. During the overlap window (--overlap-seconds,
            default 600, capped at 3600) the retired secret keeps validating
            existing tokens, so live clients never see an auth failure;
            after the window they are rejected.
key list    List active API sub-keys (metadata only, no secrets).
key revoke  Revoke an API sub-key by key ID. Immediate and durable: the
            credential stops validating and stays revoked across restarts.
key fetch   Re-fetch an agent's SSH private key from the server (GAP-128
            GetAgentKey RPC) and save it to ~/.bunker/keys/<agent-id>.
            Recovery path for a lost local key: without the key file every
            SSH-family verb (ssh/cp/pull/deploy/mount/tunnel) fails with
            "SSH key not found". The fetch is read-only server-side — it
            never rotates or regenerates the key.

All verbs require the master credential (BUNKER_TOKEN or the server entry's
static auth.token); agent sub-keys are rejected. Never use the signing
secret as a bearer token — the daemon rejects it with
"unauthenticated: invalid token".

Probe the AGENT (not the client) for the executables the remote editing
verbs depend on, and name the ones that are absent.

The verbs execute in the agent's own uid and filesystem context, so a tool
present on the client is irrelevant to them -- a fresh agent was measured to
have git and jq but not toolsd, ripgrep or a language server, which is why
search has no working output mode and lsp refuses with nothing to serve.

A missing tool is DATA (exit 0 with a named list), matching bunker probe's
contract. Only a probe that could not run exits non-zero.

With --install the tools are DELIVERED onto the agent's own PATH ($HOME/bin,
which the server already puts on every exec), then re-probed so the result is
evidence rather than a claim:
  - toolsd is copied from a locally built binary (only tools we build are
    shipped that way; a dynamically linked artifact is REFUSED, because it
    would depend on this machine's libc);
  - rg and gopls are registry tools: the delivery pulls the SAME pinned,
    signature-verified archives their package managers install (apt-get
    download + dpkg-deb -x for ripgrep; a checksum-verified Go toolchain and
    module-aware "go install" for gopls) and unpacks them into the agent's
    $HOME/bin — no root is needed and no registry trust is bypassed.
After each delivery the agent is re-probed and the install FAILS if a tool is
still unreachable — "copied the file" is not "the tool works". A local/remote
version difference on toolsd is a named warning (an operator testing one build
while an agent runs another is a silent behaviour split). On agents WITH the
image-spec path (spawn-time package-add), the same set is baked into the image
by the directive the install tail prints. Spec:
docs/prd/SPEC-agent-tool-delivery.md.

With --uninstall the delivered tools are REMOVED from the agent's $HOME/bin
(the vendored toolsd AND the registry tools the runtime stages unpacked there)
and the removal is proven the same way: the agent is re-probed through the same
audited exec path, and any removed tool still reachable on its PATH fails the
command with the survivor named. Removing an already-absent file is reported by
name, not an error — an idempotent teardown mirroring "bunker surface remove".
Tools that arrived through the image-spec package-add path live in the image's
own paths and are out of scope here.

Examples:
  bunker agent-tools abc12345
  bunker agent-tools abc12345 --json
  bunker agent-tools abc12345 --install
  bunker agent-tools abc12345 --install --binary ./dist/toolsd-linux-amd64
  bunker agent-tools abc12345 --uninstall
  bunker agent-tools abc12345 --server staging
