================================================================================
BFS-030 TRACE — the destructive half, attributed to one HTTP request
================================================================================

Instrument: the mount was built from the UNFIXED tree plus a temporary trace
line in node.Setattr (removed before the commit; the line it printed is below).
The endpoint is behind the logging reverse proxy, so every request the mount
made is in the table, with a monotonic timestamp.

### mount.log — what the kernel actually sent for the O_TRUNC open
BFS030-TRACE setattr path=src/target.txt size=0 fh_nil=true fh_type=<nil> valid=0x208

  valid=0x208 is FATTR_SIZE|FATTR_FH; fh is 0, i.e. the SETATTR names NO handle.
  That is why the fix's predicate cannot be 'the Setattr carries a handle':
  the kernel sends the same shape for a deliberate path-based resize.

  a = os.truncate(path, 32)      : no handle  -> deliberate, must keep working
  b = open('r+b') + ftruncate(0) : HANDLE      -> in-place resize (emptied the file on the unfixed tree)
  c = open('wb') + write         : no handle  -> the shell's '>', the data loss
  d = open('wb') + nothing       : no handle  -> ': > file' (a deliberate empty)
  e = os.truncate(path, 0)       : no handle  -> deliberate empty, must keep working
