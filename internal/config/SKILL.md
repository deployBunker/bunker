# Package: `internal/config`

## Public API

- `Config` — top-level bunkerd configuration struct containing `Server`, `TLS`, `Auth`, `Agent`, `Tunnel`, `NamedTunnel`, `Tailscale`, and `Audit` sections.
- `ServerConfig` — `GRPCAddr` and `RESTAddr` listeners, plus `RequestTimeout` (default 300s, was hardcoded 60s — the agent-timeout root cause).
- `TLSConfig` — enabled, file certs, certmagic AutoTLS, self-signed, mTLS, CA file, CN verification, and hosts.
- `AuthConfig` — enabled (defaults TRUE — secure-by-default, GAP-011), static token, JWT secret, JWT TTL.
- `AuditConfig` — daemon-side audit trail settings (GAP-047, cc66105): `Enabled` (defaults TRUE — every authenticated RPC is logged) and `Path` (default `/var/log/bunkerd/audit.log`). The log is append-only JSONL, file mode 0600, and never contains token values. GAP-073 (b8152f8) adds two OPT-IN retention keys, both OFF by default (a config that does not set them gets the exact pre-GAP-073 behaviour): `ShipTo` (`audit.ship_to`) ships each ROTATED segment to a remote endpoint — `https://`/`http://` webhook (segment POSTed as the request body with `X-Bunker-Chain-Head` set; the lossless copy) or `syslog://host[:port]` (RFC 3164 UDP datagrams) — fire-and-forget, so a dead endpoint never blocks or fails the audit write; `SealKey` (`audit.seal_key`) makes every rotation append a chained SEAL record to the fresh log carrying `HMAC-SHA256(key, msg=<sealed chain head>)`, letting holders of shipped copies prove a local file was truncated or replaced. Env binds: `BUNKERD_AUDIT_ENABLED`, `BUNKERD_AUDIT_PATH`, `BUNKERD_AUDIT_SHIP_TO`, `BUNKERD_AUDIT_SEAL_KEY`.
- `AgentConfig.Registry` + `AgentConfig.Reconciliation` — GAP-070 (ca01d28) durable agent lifecycle registry: an append-only JSONL event log (spawn/heartbeat/destroy) that bunkerd replays at startup so agent state survives a daemon restart. `RegistryConfig`: `Enabled` (default TRUE — a daemon restart never forgets its agents; false restores the exact pre-GAP-070 in-memory-only behaviour and `bunker registry compact` has nothing to compact), `Path` (default `/var/lib/bunkerd/agents.jsonl`, mode 0600, rotated `Path.1`…`Path.<max_backups>`), `MaxBytes` (5 MiB default), `MaxBackups` (3), `KnownIDCap` (10000 — bounds the destroyed-ID index compaction persists, which keeps a repeated destroy idempotent). `ReconciliationConfig.Mode` is `"destroy"` (default) or `"adopt"`: what bunkerd does at startup with a `bunker-*` system user the registry does not know — destroy removes it; adopt re-registers it in the tracker AND restores its exact persisted port reservation so a later spawn cannot double-allocate those ports. Validation requires `path`/`max_bytes`/`max_backups` when the registry is enabled and rejects any mode outside the two constants. Env binds: `BUNKERD_AGENT_REGISTRY_{ENABLED,PATH,MAX_BYTES,BACKUPS,KNOWN_ID_CAP}`, `BUNKERD_AGENT_RECONCILIATION_MODE`.
- `AgentConfig.Isolation` (`IsolationConfig`, GAP-075/9703082) — the per-agent `/tmp` + shared-scratch policy. The private-`/tmp` half has NO toggle (an isolation boundary that can be silently switched off is not a boundary); the knobs say WHERE the optional exchange point lives and HOW MUCH each agent may leave there: `AgentGroup` (`agent_group`, default `bunker-agents` — the isolation identity the sshd `pam_exec` precondition verifies; membership is granted to every agent whether or not scratch is enabled), `SharedScratchEnabled` (default TRUE — the bounded exchange point is on; false simply means no sanctioned cross-agent file handoff), `SharedScratchRoot` (default `/srv/bunker-share`, root-owned, setgid, mode 2750), `SharedScratchPerAgentBytes` (kernel-enforced tmpfs size cap, default 256 MiB — a scratch that cannot be mounted at the cap is NOT created at all), `PrivateTmpRoot` (default `/var/lib/bunkerd/agent-tmp`, the pam_namespace instance parent). `SharedScratchGroup` is accepted as a LEGACY alias for `AgentGroup` (first GAP-075 revision's name; an explicit alias wins over the default). `Defaults()` fills all of it from the `hostsetup` constants in one place so config, installer and daemon cannot disagree. Env binds: `BUNKERD_AGENT_ISOLATION_{AGENT_GROUP,SHARED_SCRATCH_ENABLED,SHARED_SCRATCH_ROOT,SHARED_SCRATCH_GROUP,SHARED_SCRATCH_PER_AGENT_BYTES,PRIVATE_TMP_ROOT}`.
- `ContainmentConfig` — GAP-067 containment-exposure disclosure: `Disclosure` (defaults FALSE — hidden by default; enabling makes agents disclose the managed sandbox). `ContainmentSandboxEnv` is the canonical `BUNKER_SANDBOX=1` constant (single literal; referenced by `internal/server` and `internal/agent`). Env bind: `BUNKERD_CONTAINMENT_DISCLOSURE` (overrides a config-file false). See `specs/containment-disclosure.md`.
- `AgentConfig` — base data dir, SSH dir, port ranges, max agents, default CPU/memory/disk/process/file/container limits, and TTL. `RootlessInstallerCacheDir` (`rootless_installer_cache_dir`, GAP-091) — host-level cache directory for downloaded rootless Docker installers; default `/var/cache/bunker/rootless-installer` (the daemon creates it as root, mode 0755; one ~93MB file). Empty string keeps the legacy uncached download path. Armed at daemon startup by `cmd/bunkerd` via `agent.SetRootlessInstallerCacheDir`; env bind `BUNKER_ROOTLESS_INSTALLER_CACHE_DIR` wins over the config file (empty env = unset, it never clobbers the config value).
- `TunnelConfig` / `NamedTunnelConfig` / `TailscaleConfig` — networking settings.
- `DefaultConfig()` — returns a fully populated default config.
- `Load(path string) (*Config, error)` — reads YAML from `path`, applies env-var overrides (`BUNKERD_*`), and unmarshals into a default config.
- `(*Config) Validate() error` — checks required fields and TLS mode consistency.
- `(*Config) CheckAuth() (string, error)` — startup authentication gate (GAP-011): returns a prominent `*** WARNING: AUTH DISABLED ***` message when `auth.enabled` is explicitly false, and an error when auth is enabled but neither `auth.token` nor `auth.jwt_secret` is set. `cmd/bunkerd` calls it in `run()` and refuses to start on error — the daemon never silently runs unauthenticated.

## Conventions

- Config keys map to env vars with the `BUNKERD_` prefix and underscores replacing nested dots: `BUNKERD_SERVER_GRPC_ADDR`, `BUNKERD_TLS_CERT_FILE`, etc.
- `viper.AutomaticEnv()` and explicit `BindEnv` calls cover the same keys; explicit binds ensure consistent behavior even when nested defaults change. The audit keys are explicitly bound too: `BUNKERD_AUDIT_ENABLED` and `BUNKERD_AUDIT_PATH` (GAP-047), plus `BUNKERD_AUDIT_SHIP_TO`/`BUNKERD_AUDIT_SEAL_KEY` (GAP-073/b8152f8), the GAP-067 `BUNKERD_CONTAINMENT_DISCLOSURE`, the GAP-070 registry/reconciliation keys, and the GAP-075 isolation keys (all listed per-section above).
- Default addresses are `":9090"` (gRPC/Connect) and `":8080"` (REST). Bunker production deployments typically run the REST port on `:18080`.
- Default agent port range is `10000-19999` with 100 ports per agent (100-agent capacity, matching MaxAgents 100 — GAP-010). Was `10000-10100`/10 before 4df96ec; docs and `TestDefaultConfig` both assert `19999`/`100`.
- Default `max_agents` is 100, aligned across ALL three sources (code default, config.example.yaml, README inline config) since GAP-028 (5b3fe56) — before that the docs said 50 while code defaulted to 100, a silent cap discrepancy. `TestDefaultConfig` asserts `MaxAgents == 100`.
- `config.example.yaml` at the repo root mirrors these defaults (README inline config + `DefaultConfig`) and is referenced by `bunkerd --help` (`cp config.example.yaml /etc/bunkerd/config.yaml`) and the README Configure section (GAP-008). It carries the audit section since GAP-047 (`audit.enabled: true` / `audit.path: /var/log/bunkerd/audit.log`), the GAP-070 `registry:` + `reconciliation:` sections, the GAP-075 `isolation:` section, and commented GAP-073 `ship_to:`/`seal_key:` examples (all ca01d28/9703082/b8152f8), plus the GAP-091 commented `rootless_installer_cache_dir` example.
- Default resource limits: 2.0 CPU cores, 4 GiB memory, 20 GiB disk, 4096 processes, 65536 open files, 10 Docker containers, 6-hour TTL.
- TLS modes are mutually exclusive: `auto_tls`, `self_signed`, or file-based certs. `Validate` requires `domain` for AutoTLS, `cert_file`/`key_file` for file mode, and `ca_file` for mTLS.
- Durations are `time.Duration` and parsed from YAML strings like `"6h"` or `"24h"`.

## Dependencies

- `github.com/spf13/viper` — config parsing and env binding.
- Standard library: `fmt`, `os`, `strings`, `time`.

## Test Patterns

- `config_test.go` verifies defaults, env overrides, file loading, and validation error cases.
- `TestDefaultConfig` asserts the full default surface: port range `19999`/`100` (GAP-010), `MaxAgents == 100` (GAP-028), auth enabled (GAP-011), 6h default TTL, audit enabled with default path `/var/log/bunkerd/audit.log` (GAP-047), the GAP-070 registry ON at `/var/lib/bunkerd/agents.jsonl` with reconciliation `destroy` (ca01d28), and the GAP-075 isolation defaults (9703082).
- Tests use `t.Setenv` to exercise `BUNKERD_*` env var bindings without touching real files. `TestLoad_AuditEnvOverrides` covers `BUNKERD_AUDIT_ENABLED=false` + a custom `BUNKERD_AUDIT_PATH`; a config-file test covers an explicit `audit.enabled: false` and custom `audit.path` in YAML. GAP-067 adds the containment battery: default-false (`TestDefaultConfig_ContainmentDisclosureDisabled`), env override (`BUNKERD_CONTAINMENT_DISCLOSURE=true`), env-beats-file, and file-true. GAP-073 (b8152f8) adds `TestAuditConfigShipToAndSealKey`. GAP-070 (ca01d28) is covered by the dedicated `registry_config_test.go`: defaults (incl. `TestConfigConstantsMatchRegistryPackage`, which pins the config defaults to the `internal/registry` package constants), the `Defaults()` zero-fill helper, reconciliation-mode validation (`TestConfigValidateRejectsBadMode`), and file+env loading. GAP-075 isolation keys get `TestIsolationAgentGroupDefaults`, `TestIsolationAgentGroupLegacyAlias` (shared_scratch_group alias), and `TestLoad_IsolationAgentGroupFromFile` (9703082).
- Validation tests cover all TLS modes: missing certs, AutoTLS without domain, mTLS without CA file, and valid combinations.
- Tests assert default values are populated even when the config file is absent.

## Pitfalls

1. **`viper` env binding requires underscores, not dots.** YAML keys like `server.grpc_addr` map to `BUNKERD_SERVER_GRPC_ADDR`. Passing `BUNKERD_SERVER.GRPC_ADDR` will not work because viper's replacer is configured with `strings.NewReplacer(".", "_")`.
2. **`Load` returns defaults when the file is missing.** This is intentional for container bootstrapping, but it means `Validate` must be called explicitly to catch missing required fields.
3. **TLS self-signed mode fills in default cert/key paths.** If `cert_file` or `key_file` are empty and `self_signed` is true, `Validate` sets them to `/etc/bunkerd/tls/cert.pem` and `/etc/bunkerd/tls/key.pem`; callers must generate the files before enabling TLS.
4. **`JWTSecret` is used as both signing key and apikey manager seed.** The `apikey.Manager` is initialized with `cfg.Auth.JWTSecret`; rotating the JWT secret invalidates all opaque agent sub-keys.
5. **Port ranges are `uint32`, not `int`.** Negative values or values > 65535 cannot be represented, but zero values can accidentally disable allocation if `PortRangePerAgent` is 0.
6. **Request timeout defaults to 300s but was historically hardcoded 60s.** `server.request_timeout` / `BUNKERD_SERVER_REQUEST_TIMEOUT` overrides it. Agent exec/timeout complaints on a deployed server are usually the old 60s binary — pull latest and rebuild.
7. **Auth is enabled by default — a credential-less daemon refuses to start (GAP-011).** With no config file, `bunkerd` exits with `refusing to start: auth.enabled is true but neither auth.token nor auth.jwt_secret is set`. Batteries and test fixtures set `auth.enabled: false` explicitly; an explicit disable prints `*** WARNING: AUTH DISABLED ***` to stderr. A default config without credentials is a STARTUP ERROR, not a silent unauthenticated run.
8. **Audit is enabled by default, but an unwritable `audit.path` does NOT block startup.** The server opens the audit log in `New` and only warns (`"audit logging disabled"`) on failure — the daemon keeps running without audit. Missing parent directories are created with mode 0700 and the log file itself with 0600, but a read-only filesystem or permission problem silently degrades to no audit trail. Check the daemon log if records are expected but absent. GAP-073 softens this further on purpose: an INVALID `audit.ship_to` is likewise non-fatal — the daemon warns `audit shipping disabled` (endpoint redacted) and keeps a plain local log, so a typo in a shipping endpoint must never cost the trail itself.
9. **`agent.reconciliation.mode` decides the fate of real host users at startup.** `destroy` (default) removes any `bunker-*` system user the replayed registry does not know; `adopt` keeps it and restores its exact persisted port reservation. Both modes also purge stale replayed records — pick `adopt` deliberately for a host whose agents you want to survive, and never point two daemons at one registry file.
10. **The registry is ON by default and fails the daemon closed.** A bunkerd that cannot open/persist `agents.jsonl` refuses to serve (`agent registry unavailable`) instead of accepting spawns it would forget on the next restart (GAP-070, enforced in `internal/server`). Disable it only deliberately (`agent.registry.enabled: false`), knowing restarts then lose all agent state.
