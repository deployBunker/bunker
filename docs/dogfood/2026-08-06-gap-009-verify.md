## 3. Follow-up bug found by the verification (fixed tick #231)

`bunker cp` initially FAILED from kara with `scp: Connection closed` (exit 255)
and `ssh: Too many authentication failures`, while `bunker exec` worked.

Root cause: client ssh/scp command builders passed `-i <key>` but not
`-o IdentitiesOnly=yes`. With a loaded ssh-agent (kara holds fleet keys), ssh
offers ALL agent keys before the correct identity; the server's MaxAuthTries
limit kills the connection. The exec path runs server-side, so it was immune —
the battery's on-server verification could never catch this class of failure.

Fix (foreman-direct, Exception 7 — mechanical, one flag): added
`-o IdentitiesOnly=yes` to:
- `buildSCPArgs` + chown ssh in `internal/cli/cp.go`
- chown ssh in `internal/cli/deploy.go`
- sshfs args in `internal/cli/mount.go`
- `clientTunnelArgs` (injects if absent) + `rewriteTunnelCommand` display in `internal/cli/sshhost.go`
- server-side spawn bundle in `internal/agent/manager_spawn.go`

Tests: `sshhost_test.go` TestClientTunnelArgs (4 cases incl. no-duplicate
injection) + TestRewriteTunnelCommand expectation updated; build/vet/gofmt
clean; `go test ./internal/cli/ ./internal/agent/` PASS.

Re-verified live after fix: cp PASS, deploy PASS, tunnel PASS (docker through
forwarded socket), destroy clean.
