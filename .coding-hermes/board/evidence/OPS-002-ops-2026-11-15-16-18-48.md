## 2. The mechanism, attributed

Every 502 failure since 2026-11-12 was spawned against one gateway URL:

```
$ sqlite3 -readonly ~/.hermes/scheduler.db "select gateway_url, gateway_source, count(*) from ticks where error like '%502%' and outcome='failed' and created_at>'2026-11-12' group by 1,2;"
http://127.0.0.1:9391|global|168
```

:9391 is not the Hermes gateway — it is the task-router proxy:

```
$ ss -ltnp | grep :9391
LISTEN 0 5 127.0.0.1:9391 ... users:(("python3",pid=2083838,fd=3))
$ tr '\0' ' ' < /proc/2083838/cmdline
/usr/bin/python3 /home/kara/task-router/scripts/router_server.py --mode read-only --host 127.0.0.1 --port 9391
$ ps -o lstart= -p 2083838
Sat Nov 14 07:58:39 2026
$ pgrep -af schedulerd | head -1   (gateway flag)
--gateway-url=http://127.0.0.1:9391 --no-exec-fallback --max-concurrent 16 --tick-timeout 3h
```

`router_server.py` answers 502 after exhausting its hop retries (`return (status if isinstance(status,int) and status>=400 else 502), out`), with a per-hop wall (`ROUTER_PROXY_HOP_WALL_S`, default 3600; the historical comment records a 600s hop wall producing "502 after 553s"). The scheduler records the body verbatim:

```
gateway HTTP 502 and exec fallback disabled: gateway POST: HTTP 502: {"error": "timed out"}
```

Wall times and telemetry of the failing ticks show this is a mid-flight death, not a fast rejection:
