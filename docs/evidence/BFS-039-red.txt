READ IT: `flushed=true, failure=<nil>` is the tell. The retry did not take the
failure branch — its Seek failed, because the first (cancelled) attempt had handed
the buffer file to net/http, which closes a request body on every failed round
trip. Whether it fired depended on whether the request had started first, which is
why 5 of 12 runs failed and 7 passed: an intermittent, byte-shaped defect in a
write path. The deterministic arm (a server that holds the PUT open until the
cancel has landed) was written because of this capture.

5. THE CONTROLS THAT WERE NOT RED, reported as such
--------------------------------------------------------------------------------
(a) THE KILLED READER AND THE KILLED REFRESHER (BFS-046 cells 8a/8b) PASS on the
    pre-fix tree. BFS-038's representation is why: the path index is the only way
    to a blob, an interrupted refresh is unreachable rather than half-visible, and
    the reopen sweeps the staged residue. No red was manufactured for the cache's
    reader half.

(b) THE PER-PATH COMMIT LOCK was not held by anything dead, on either tree: the
    lock is a striped array of in-process mutexes, so a killed process cannot
    leave it held. The measurement that would expose the alternative — lock
    artifacts in the directory at rest and after a SIGKILL — reads 0 on both
    trees, and the sensor that measures it is exercised by its own control
    (a real stale lock file must be seen).

(c) THIS ROW'S OWN FIRST IDEMPOTENCE CELL was BLIND, and the arms found it: the
    `non-positional-write` mutation (WriteAt -> Write) left it GREEN, because a
    retry from a NEW handle starts from a fresh buffer. The cell was rewritten
    (same offset twice on ONE handle; a misordered pair) and the mutation now
    turns it red. Recorded here because a cell that cannot fail proves nothing,
    and the controls are how that gets caught.
