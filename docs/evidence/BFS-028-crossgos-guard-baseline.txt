=============================================================================
THE SECOND DEFECT, PRECISELY (for the row that owns it)
=============================================================================
internal/fsmount/platform_unsupported_test.go:110

    st := m.Status()
    if st != (fsclient.Status{}) {     // <- does not COMPILE for !linux targets

`fsclient.Status` is not a comparable type: its `Cache CacheStats` field
(internal/fsclient/status.go:86) carries `BypassReasons map[string]int64`
(internal/fsclient/cache.go:256). Go therefore rejects `!=` on the struct.

- It has never been caught because the file is `//go:build !linux`: on the host
  that runs every test in this repo it is not compiled at all. Only `go vet` for a
  non-linux target compiles it — which is exactly the check
  internal/fsmount/fs_unsupported.go's own header says exists to catch this
  ("A seam that is only ever compiled on one platform has not been checked").
- The guard has therefore been red on that lane since `BypassReasons` was added,
  and the red lane is worth more than the defect: it means item 2 of
  probes/cross-GOOS-build.sh has NOT been running as a check for that window.
- The fix is one line, and the choice is the owner's: `reflect.DeepEqual(st,
  fsclient.Status{})` if the assertion means "the whole document is the zero
  value", or assert the fields the test actually cares about (the two empty
  strings and the empty verdict, which the neighbouring assertions already do).
  Fixing it needs the same RED/GREEN discipline as any other cell: the file
  compiles for windows/amd64 BEFORE the change only in the failing sense, so the
  GREEN is `GOOS=windows go vet ./internal/fsmount` exit 0 and the RED is the
  output above — re-runnable with the two commands in this file.
