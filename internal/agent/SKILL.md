# Package: `internal/agent`

## Public API

- `AgentManager` — lifecycle manager for isolated Linux agents.
- `NewAgentManager(cfg, logger, tracker, tunnelMgr, tailscaleMgr)` — constructor; builds a port allocator, tracker, and starts the TTL reaper.
- `(*AgentManager) Spawn(ctx, *SpawnAgentRequest) (*SpawnAgentResponse, error)` — creates a Linux user, generates an SSH keypair, writes `authorized_keys` and `.profile`, installs rootless Docker, and starts dockerd via systemd-run with cgroup limits. Invalid `--ttl` values are rejected here (step 1a, before port allocation) with `CodeInvalidArgument` — no silent fallback to the default.
- `(*AgentManager) Destroy(ctx, agentID, force) (*DestroyAgentResponse, error)` — stops dockerd, removes user slice limits, and removes the Linux user with `userdel -rf`. Unknown IDs return a clean `agent %q not found` `CodeNotFound` error; raw `userdel` output is confined to the server log, never the user-facing error (DOGFOOD-005). Removal is retried (20×500ms after `pkill -u -9` of lingering procs) so a slow dockerd shutdown can't lose the race and leak users (GAP-001/GAP-007).
- `(*AgentManager) provisionIsolation(ctx, agentID, username, uid, gid) error` / `removeIsolation(ctx, agentID)` (isolation.go, GAP-075) — the daemon's half of the isolation boundary, with two different failure policies. The **agent-group membership is mandatory**: the sshd `pam_exec` precondition verifies it before `pam_namespace` runs, so an agent that cannot join the group has every session DENIED — a failure returns an error and `Spawn` rolls back (`cleanup()` + error) instead of leaving an agent that cannot open a session (it never falls back to the shared `/tmp`). The **shared-scratch directory** (`hostsetup.EnsureAgentScratch`) and the **private-/tmp instance directory** (`hostsetup.EnsureAgentTmpInstance`) are best-effort with loud warnings: a scratch that cannot be BOUNDED is never replaced by an unbounded directory (fail-closed lives in `internal/hostsetup`), and the instance directory is recreated by pam_namespace on the first session anyway. `provisionIsolation` is called by `Spawn` after `useradd` and its error is fatal there; membership is granted regardless of `shared_scratch_enabled`.
- `(*AgentManager) hostSetup() hostsetup.Options` (isolation.go, GAP-075/9703082) — builds the manager's host-provisioning options from `cfg.Agent.Isolation` (after `Defaults()`): agent group, scratch root + per-agent cap, private-`/tmp` instance root. The `hostRunner` seam (when set) replaces the command runner so spawn/destroy isolation provisioning is testable without root.
- `(*AgentManager) removeIsolation(ctx, agentID)` (isolation.go, GAP-075/9703082) — destroy-side teardown: removes the agent's shared-scratch directory and private-`/tmp` instance directory (`hostsetup.RemoveAgentScratch` / `RemoveAgentTmpInstance`). Both removals are idempotent, so a partially provisioned (or never provisioned) agent destroys cleanly; failures are loud warnings, never a failed destroy.
- `buildRootlessDockerdArgs(dockerdUnitArgs) ([]string, []string)` (isolation.go, GAP-075) — pure builder for the rootless-dockerd `systemd-run` argv + `--setenv` environment, so the unit properties (including `--property=PrivateTmp=yes`) are pinned by unit tests instead of by a live host. `lookupAgentUser` is a variable seam so the spawn-time isolation wiring can be tested without root.
- Spawn-failure rollback + stage attribution (INT-CI-005, 94f828b) in `spawn_failure.go` / `manager_spawn.go`: the server wraps handlers in chi `middleware.Timeout` (`internal/server/server.go`, 300s default), so when a spawn hits the request deadline the ctx handed to `Spawn` is ALREADY CANCELLED by cleanup time — and `exec.CommandContext(ctx, ...)` on a cancelled ctx never runs the command at all. The rollback closure therefore derives a DETACHED context (`rollbackContext`: `context.WithoutCancel(ctx)` + a 60s `WithTimeout`, `spawnRollbackTimeout`) and runs every compensating action on it: port-range free, slice-dropin removal (`removeUserSliceLimits`), `userdel -r` (`removeAgentUser`, pkill-then-retry-once inside the same detached ctx), key removal, `removeIsolation`. Without this, a timed-out spawn stranded a HALF-CREATED agent (Linux user present, no `/etc/bunkerd/ssh/<id>` key, no registry row). Every failure return from `Spawn` flows through `fail(stage, cause)` → `spawnStageErr` (`spawn %s failed at stage %s: ...`, `%w` preserves the cause) and appends one JSON breadcrumb line to `/var/lib/bunkerd/spawn-failures.jsonl` (`spawnFailureBreadcrumbPath`, package var; `spawnBreadcrumb`: timestamp, agent_id, stage, context_error, error, rollback_ran, rollback_failed; best-effort — a failed write warns and never fails the spawn). The 13 named stages in execution order: `validate`, `capacity`, `port-alloc`, `user-create`, `isolation-provision`, `keygen`, `authorized-keys`, `rootless-install`, `dockerd-start`, `container-cap`, `image-build`, `slice-limits`, `register`; a cancelled/expired request ctx additionally names the server request timeout (`request_timeout`, default 300s). The three slow stages (`rootless-install`, `dockerd-start`, `image-build`) log `spawn entering stage` so the journal shows progress up to a cancellation point.
- `ParseAgentTTL(s string) (time.Duration, error)` — TTL parser in `ttl.go` (DOGFOOD-003). Accepts the spec `\d+[hmd]` including day values (`7d` → 168h, which `time.ParseDuration` never supported); rejects invalid/negative/zero/overflowing input. Shared by Spawn validation AND the API-key TTL block so agent and key expiry always agree.
- `(*AgentManager) Heartbeat(agentID, ttl) (*resource.AgentRecord, error)` (manager.go) — extends an agent's expiry with the manager's never-SHRINK rule: the candidate expiry is applied only when it is AFTER the recorded one, so a short heartbeat can never cut a long TTL short (which would destroy the agent on expiry); an unknown id is a clean `agent %q not found`. The extended expiry is best-effort durable (a failed registry append is logged, not fatal).
- `(*AgentManager) Reconcile(ctx) ReconcileReport` (reconcile.go, GAP-070) — the startup replay of the durable registry against host state (purge stale records, restore live ones with their EXACT port reservation, adopt or destroy orphans, then unblock the TTL reaper). It never fails hard: every action is logged and the daemon keeps running. `ReconcileReport` is the summary — `Mode`, `ReplayedLive`/`ReplayedKnown`, `SystemAgents`, `Restored`, `Purged`, `Adopted`, `Destroyed`, and `Foreign` (orphans left completely untouched because they belong to ANOTHER daemon instance — see the ownership-marker entry below); `internal/server/server.go` logs all of them at startup, including `foreign`.
- `SystemAgent` (reconcile.go) — one managed user found on the host by `listSystemAgents`: `AgentID`, `Username`, `Home`. It is the input type of the foreign/ownership classification and is injectable, so reconciliation is testable without root or real `bunker-*` users.
- `(*AgentManager) RegistryError() error` (manager.go) — why the durable registry is unavailable, or nil when it is fine. Any process that must serve traffic checks it (server.Run does); tests and one-shot callers may ignore it.
- Stamping is part of `Spawn`: it also writes this daemon's ownership marker into the agent's `.bunker` metadata directory (`writeOwnerMarker`, DF-BUNKER-18): two lines, `<daemon-instance-id>\n<pool-start>-<pool-end>\n`, written next to `.bunker/ports` and inside the same `chown -R` the port file gets. Best effort like the port file (a write failure warns and never changes spawn's success criteria), and NO file is written when this daemon has no identity of its own — an absent marker degrades to the legacy handling instead of fabricating ownership this daemon cannot honour. The pool line is operator diagnostics only and never takes part in the ownership decision.
- `(*AgentManager) Stop()` — signals the TTL reaper goroutine to exit.
- `(*AgentManager) RunAgent(ctx, *v1.RunAgentRequest)` — detached execution as a systemd transient unit (run.go). GAP-067: `buildRunAgentArgs` takes a trailing `disclosure bool`; when the daemon runs with `containment.disclosure` enabled, detached units get `--setenv=BUNKER_SANDBOX=1` (canonical constant `config.ContainmentSandboxEnv`), absent when disabled (argv byte-identical). The disclosure value is ADMIN-CONTROLLED: an agent-supplied env override for the same key can neither suppress nor rewrite it when disclosure is enabled.
- SSH key auto-provisioning in `host_key.go` (UX-007):
  - `provisionHostSSHKey(ctx, username, authKeysFile, logger)` — scans the host's `/root/.ssh/id_{ed25519,rsa}.pub` and appends the public key to the agent's `~/.ssh/authorized_keys` during spawn, so the host can SSH into agents without a manual key exchange.
  - `findHostPublicKey()` — returns the first available host public key path and contents; no key → warning, not error.

Rootless helpers in `rootless.go`:
- `configureSubIDs(username)` — ensures `/etc/subuid` and `/etc/subgid` entries for rootless Docker.
- `installRootlessDocker(ctx, username, userHome, logger)` — downloads and installs Docker's rootless extras into the agent home. The user-manager bring-up it depends on is no longer an inline destructive preamble: it delegates to `bringUpUserManager` (INT-CI-008, see the ordering block below), and the post-bring-up `MkdirAll(0700)`/non-recursive `chown` of `/run/user/<uid>` is kept only as insurance for the install step — it is no longer the only place the directory is created.
- `removeMountsUnder(ctx, dir, logger)` — lazily unmounts (`umount -l`) any filesystems mounted at/under dir; it is called by `resetUserManagerState` immediately before that reset removes the runtime directory (and never on the fresh path, where no reset runs at all). On desktop-flavoured hosts (Ubuntu + GNOME) the systemd user manager mounts gvfsd-fuse at `/run/user/<uid>/gvfs`; without allow_other that FUSE mount blocks `rm -rf` ("Device or resource busy") and denies even root on recursive chown (2ed1054).

User-manager bring-up ordering (`rootless.go`, INT-CI-008 — the regression that failed the E2E battery):

- `bringUpUserManager(ctx, username, uid, stdRuntimeDir, logger)` — owns the ORDERED bring-up and is the only entry point `installRootlessDocker` uses: (1) reset stale user-manager state ONLY when there is proven stale state, (2) create + ownership-VERIFY `/run/user/<uid>`, (3) `loginctl enable-linger`, (4) `ensureUserManagerRunning`, (5) `waitForUserManager`. Steps 2-before-4 is load-bearing: on systemd 255 `user@<uid>.service` carries no Requires/After on `user-runtime-dir@<uid>.service`, so nothing creates the directory for a manager start — with it missing, `pam_systemd` refuses to set `XDG_RUNTIME_DIR` ("Failed to stat() runtime directory"), `systemd --user` exits 1 and the unit can NEVER go active. Step 2 also precedes step 3 because enabling linger can itself attempt a manager start.
- `classifyRuntimeDir(info, probeErr, uid) (stale bool, reason string)` — decides whether an observed runtime directory carries a PREVIOUS user's state (must be reset) or is the fresh path (must not be touched). Readable through the `runtimeDirProbe` seam (`probeRuntimeDirOnDisk`, which uses `Lstat` so a symlink is never mistaken for a directory). It fails SAFE: an unreadable probe, a non-directory entry and an unknowable owner all count as STALE, so the historical reset is kept rather than silently skipped.
- `resetUserManagerState(ctx, uid, runtimeDir, logger)` — the CONDITIONAL reset, and it is state-consistent: `systemctl stop user@<uid>.service`, `loginctl terminate-user <uid>`, `removeMountsUnder`, `systemctl stop user-runtime-dir@<uid>.service` (so logind's `RemainAfterExit` state matches the filesystem instead of claiming a directory it no longer owns), then remove the directory. Every step is best effort (`userManagerRunner` seam). **The fresh path issues no stop, no `loginctl terminate-user` and no `rm` at all** — the old code ran that preamble unconditionally on every install, which both destroyed state a brand-new recycled uid had nothing to do with and left the directory missing for the manager start.
- `ensureUserRuntimeDir(ctx, username, uid, stdRuntimeDir, logger) error` — guarantees the directory exists and is owned by uid BEFORE any manager start: starts logind's own `user-runtime-dir@<uid>.service` as a BEST EFFORT first (`RemainAfterExit`, so a start on an already-active unit is a no-op even with the directory gone), then `MkdirAll(0700)` + a NON-recursive `chown username:` (a recursive one descends into a gvfsd-fuse mount and fails even as root), then VERIFIES existence, type and owner via `runtimeDirProbe` and returns a loud error for each mismatch instead of starting a manager that cannot come up.
- `fetchUserManagerJournal(ctx, unit, logger) string` + `condenseJournal(raw)` — attribution for a failed start: the systemd job Result does not name the cause (the line that mattered was `pam_systemd` reporting the missing runtime directory). Bounded and best effort — `journalctl --no-pager -u <unit> -n 20` first, `systemctl status --no-pager -n 20` as fallback, empty string when neither is readable, a 5s timeout DETACHED from the caller's deadline (`context.WithoutCancel`, so attribution still works after the client gave up), one line with fragments joined by ` | ` and truncated at a rune boundary (400 chars). It rides the terminal error as `: journal=<excerpt>` and the WARN alongside `linger_entries`; the error is built with `errors.New`, never `fmt.Errorf`, because host output must not be re-interpreted as a format string. The sub-stage name stays `user-manager-start`, so the `spawn_failure.go` taxonomy is unchanged.
- `userManagerUnitName(uid)` / `userRuntimeDirUnitName(uid)` — the two unit names (`user@<uid>.service`, `user-runtime-dir@<uid>.service`) as typed helpers, so the reset/start paths cannot drift apart.

Cross-daemon ownership marker (`registry.go` + `reconcile.go`, DF-BUNKER-18 — two daemons on one host with OVERLAPPING port pools):

- `loadOrCreateDaemonInstanceID(baseDataDir, logger)` — this daemon's restart-stable identity, resolved ONCE by `NewAgentManager` from `<base_data_dir>/instance` (0600, 32 random hex chars, `O_CREATE|O_EXCL` so two concurrently starting daemons cannot each walk away with a different id — the loser reads the winner's file). Regenerating per start is forbidden: a fresh id every restart would make this daemon's own previously-spawned agents read as FOREIGN and leak forever. Every failure (no `base_data_dir`, unreadable, empty file) is returned and logged as a warning, never fatal: the identity stays empty, which disables the ownership check and leaves the legacy behaviour in place.
- `ownerMarkerFilename` (`owner`) / `persistedOwnerPath(home)` / `readPersistedOwner(home)` — read `<home>/.bunker/owner`, whose first line is the instance id and whose second is the informational pool fingerprint. `ok` is true only when line 1 carries a non-empty id; an unreadable file, an empty file or an empty line 1 all mean "no marker" and the caller falls back to legacy handling. The pool line is parsed leniently and never participates in the decision.
- `(*AgentManager) writeOwnerMarker(metaDir)` / `poolFingerprint()` — the spawn-time writer described above; `poolFingerprint` renders `<start>-<end>` from the allocator's `Bounds()` (falling back to the configured range when no allocator is active) purely for operator diagnostics.
- `(*AgentManager) orphanIsForeign(sa) (foreign bool, start, end uint32)` — the ownership decision, in precedence order: (1) a marker naming ANOTHER instance ⇒ FOREIGN, checked FIRST and independently of the port range, which is what also covers OVERLAPPING pools and missing/unreadable port metadata — the two destructive shapes the port test alone could not classify; (2) a marker naming THIS daemon ⇒ NOT foreign, and the port test is deliberately not applied (the agent is ours; a disjoint range is a leftover from our own older pool geometry and takes the ordinary adopt/destroy decision, fail-closed included); (3) no marker (or no identity of our own) ⇒ the legacy behaviour byte for byte, i.e. a persisted range ENTIRELY disjoint from our pool is foreign while unreadable/malformed metadata is NOT (the daemon cannot prove it is safe to leave). A foreign orphan is never adopted AND never destroyed, not even in destroy mode; every skip is one loud warning (`logForeignOrphanSkip`) naming the agent, its persisted range (0-0 when unreadable), our pool, and — when readable — the owning instance id and the pool geometry that daemon recorded.
- `ReconcileReport.Foreign` counts those skips and `internal/server` logs the field at startup, so a two-daemon host is visible rather than silently destructive. Note the deliberate asymmetry: the pool line inside the marker is NOT part of the decision — a legitimate pool-geometry change on THIS daemon would otherwise reclassify its own agents as foreign and leak them forever.
- `ensureRootlesskitAppArmor(ctx, username, logger)` — writes an AppArmor profile for rootlesskit on Ubuntu 24.04+.
- `waitForUserManager(ctx, runtimeDir)` — waits for the systemd user manager bus socket before running the installer.

## Conventions

- Every agent runs as a dedicated `bunker-<agent-id>` Linux user.
- The spawn bundle's docker-host tunnel command includes `-o IdentitiesOnly=yes` (GAP-009/c238df4) so clients with loaded ssh-agents can't exhaust the server's `MaxAuthTries` before the agent key is offered.
- Agent IDs must match `^[a-z0-9-]{1,63}$`; empty IDs are replaced with a UUID short segment.
- Private SSH keys are persisted under `cfg.Agent.SSHDir` (`/etc/bunkerd/ssh` by default) for server-side use; the public key is written to the agent's `~/.ssh/authorized_keys` with an `environment="DOCKER_HOST=..."` prefix.
- Docker socket is created at `/run/bunker/<agent-id>/docker.sock` and chowned to the agent user.
- Resource limits come from `SpawnAgentRequest.Limits` or server defaults in `config.AgentConfig`; the same `AgentConfig.Isolation` section (`agent_group`, `shared_scratch_*`, `private_tmp_root` — GAP-075/9703082) feeds the spawn/destroy isolation provisioning above.
- **GAP-075 isolation:** every transient unit carries `--property=PrivateTmp=yes` (rootless dockerd AND detached `RunAgent`), and `TMPDIR` is `config.IsolationTmpDir` (`/tmp`) in every injected environment — units, `authorized_keys` `environment=`, `.profile`, and the `env(1)` prefix of all exec modes. `/run/bunker/<id>/tmp` is still created (0700, agent-owned) as a legacy per-agent scratch path but is NOT advertised as `TMPDIR`: a directory in a shared mount namespace is not a boundary. SSH sessions get their private `/tmp` from pam_namespace (host-provisioned, `internal/hostsetup`), which applies only to members of the agent group the daemon grants at spawn; the daemon cannot provide the per-session mount itself, so it must not claim `TMPDIR` alone as isolation.
- systemd-run uses `--system --uid=<UID> --gid=<GID> --property=PAMName=login` plus `CPUQuota`, `MemoryMax`, `LimitFSIZE`, `TasksMax`, and `LimitNOFILE` properties (LimitFSIZE: set default_disk_bytes: 0 in config — a finite RLIMIT_FSIZE crash-loops .NET apps at first boot, 2ed1054).
- The `XDG_RUNTIME_DIR` for rootlesskit is set to `/run/bunker/<agent-id>/run` so dockerd can start even when the standard `/run/user/<UID>` path is unavailable.
- The standard runtime dir `/run/user/<UID>` is created and ownership-VERIFIED before the manager start (`ensureUserRuntimeDir`), then chowned NON-recursively (`chown user: dir`, no `-R`): a recursive chown descends into a gvfsd-fuse mount and fails with "Permission denied" (FUSE without allow_other denies even root) (2ed1054). The runtime directory must exist BEFORE `user@<UID>.service` starts — a manager started without it can never go active (INT-CI-008) — and the stale-state reset that used to precede every install is now CONDITIONAL on `classifyRuntimeDir` proving the directory carries a previous user's state.

## Test Patterns

- Tests are table-driven where possible; heavy integration paths are mocked with `exec.Command` and temp directories.
- `manager_test.go` uses a `fakeAgentManager` and helper fake useradd/userdel scripts placed on `PATH` to avoid requiring root.
- `manager_dockerd_test.go` tests `waitForDockerd` with a temp directory and a stub process running as the current user.
- `rootless_test.go` uses a temp copy of `/etc/subuid`/`/etc/subgid` via package-level vars to verify subID mapping without touching real system files.
- `concurrency_test.go` exercises the port allocator under goroutines to prove disjoint ranges.
- `gap075_test.go` (9703082) pins the isolation wiring behaviourally without root: exact `buildRootlessDockerdArgs` argv/env (PrivateTmp + TMPDIR present, and limit properties OMITTED when the corresponding limit is 0), detached `RunAgent` units carry PrivateTmp, `provisionIsolation` provisions the bounded scratch + instance and still grants membership when scratch is DISABLED, a membership failure is fatal to spawn (fail-closed, no host `/tmp` fallback), destroy runs `removeIsolation`, `TestSpawnWiresIsolation` drives the full spawn path with a fake runner, and `TestResetStaleDockerdUnit` covers the stale-unit reset.
- `ttl_test.go` uses a fast fake clock (`fakeTimeNow`) to verify TTL expiry reaping without wall-clock waits; the TTL parser itself is covered by a 28-case table test (valid `6h`/`90m`/`24h`/`7d`→168h; rejects banana/0/-1h/1.5h/empty/overflow).
- `rootless_runtimedir_test.go` (INT-CI-008, bb751f5) drives the WHOLE user-manager bring-up through the `userManagerRunner` seam (plus `runtimeDirProbe`), so no root and no live host are needed: `TestBringUpUserManager_FreshPathIsNonDestructive` (no stop, no `loginctl terminate-user`, no `rm` on the fresh path), `_StaleRuntimeDirTriggersReset` (and its order), `_FailedStartCarriesJournalReason` (journalctl and `systemctl status` arms — the returned error names `pam_systemd`/`XDG_RUNTIME_DIR`), `TestEnsureUserRuntimeDir_VerifiesOwnership` (existence, type and owner are checked BEFORE the manager start, with the argv order pinned so the runtime-dir bring-up + chown precede it), `TestClassifyRuntimeDir_FailsSafe` (the probe-failure / non-directory / unknown-owner matrix all classify as stale), plus `TestCondenseJournal` and `TestInstallRootlessDocker_BringUpStillFirst`.
- `reconcile_owner_test.go` (DF-BUNKER-18, eab2c0a) pins the marker contract end to end: `TestReconcile_ForeignOwnerMarkerIsNeverAdoptedOrDestroyed` (another instance's marker survives in destroy mode with no adopt attempt), `TestReconcile_OwnOwnerMarkerKeepsTodaysHandling`, `_OwnOwnerMarkerStillFailsClosedWithoutPortMetadata`, `_OwnOwnerMarkerWithDisjointPortsTakesTheNormalPath`, `TestOrphanIsForeignClassification` / `_LegacyCasesWithInstanceIdentity` / `_WithoutAllocatorNeverSkipsByPorts`, `TestReadPersistedOwnerParsing`, `TestOwnerMarkerWriterMatchesReconcileReader` (the writer's bytes and the reader's parser are pinned against each other), `TestDaemonInstanceIDIsStableAcrossRestarts` and `TestDaemonInstanceIDUnavailableDegradesToLegacyOwnership`. `reconcile_foreign_test.go` (DF-BUNKER-13, e0a6093) covers the port-disjointness arm and the `Foreign` counter.
- `spawn_failure_test.go` (INT-CI-005, 94f828b) — hermetic PATH-stub pattern, non-root, no `/var/lib` writes (tests redirect `spawnFailureBreadcrumbPath` to `t.TempDir()`): `TestSpawnRollbackRunsUserdelUnderCancelledContext` creates a user, cancels the spawn mid-keygen via the request budget, and asserts userdel was STILL invoked (RED-proof: rewiring the closure back to the request ctx reproduces `userdel ...: context deadline exceeded` with zero stub invocations), plus stage/timeout attribution in the error and exactly one breadcrumb line; `TestSpawnFailureBreadcrumbCancelledSpawn` pins the one-JSON-line shape (agent_id, stage, context_error, rollback_ran/rollback_failed, RFC3339 timestamp); `TestRemoveAgentUserRetryTable` covers retry-after-pkill success, failure bounded at 2 attempts, and cancelled-ctx-runs-no-exec; `TestSpawnStageErrWrapsCauseAndNamesTimeout` + `TestSpawnStagesCoverNamedStages` pin the error-text contract and the stage vocabulary.
- Root-gated suite (`go test -run 'TestSpawn|TestCgroup|TestConcurrency'` as root — spawns REAL users): coverage tests that spawn agents MUST `defer cleanupAgent` (GAP-001/007). Assertions tolerate OOM kills (Go `ExitCode()` returns -1 for signal deaths, not shell 137 — assert `WaitStatus`) and collapsed systemd `show` forms (`LimitNOFILE`/`LimitFSIZE` print a single value when soft==hard) (GAP-001, 1afa140).
- Avoid tests that require a real dockerd; instead assert systemd-run argument construction and file-system state.

## Pitfalls

1. **Rootless Docker requires lingering before install — and the runtime directory before the MANAGER.** The systemd user manager must exist for `dockerd-rootless-setuptool.sh` to run `systemctl --user`. `installRootlessDocker` calls `bringUpUserManager`, which creates and ownership-verifies `/run/user/<UID>` BEFORE starting `user@<UID>.service` and then waits for the manager bus socket (`/run/user/<UID>/bus`); without this, install fails with `Unit docker.service not found`. Inverting those two steps is the INT-CI-008 regression: on systemd 255 nothing else creates the directory, `pam_systemd` refuses `XDG_RUNTIME_DIR`, and the manager exits 1 forever.
2. **dockerd-rootless.sh defaults `--detach-netns=true` which breaks rootlesskit v1.1.1.** The manager sets `DOCKERD_ROOTLESS_ROOTLESSKIT_DETACH_NETNS=false` and passes `DOCKERD_ROOTLESS_ROOTLESSKIT_NET=slirp4netns` for compatibility.
3. **Stale systemd units from incomplete destroys block re-spawn.** Before `systemd-run`, the manager runs `systemctl stop/disable/reset-failed` on the unit name and calls `stopDockerdDirect` as a fallback; otherwise `systemd-run --unit=` fails with "already loaded".
4. **Port allocator can be disabled.** If `PortRangeStart >= PortRangeEnd` or `PortRangePerAgent` is invalid, `NewAgentManager` logs a warning and leaves `portAlloc` nil; `Spawn` falls back to the full configured range.
5. **systemd-run `--system --uid` does not inherit the caller's environment.** Every needed env var (`PATH`, `HOME`, `USER`, `XDG_RUNTIME_DIR`, `DOCKER_HOST`, etc.) must be passed explicitly via `--setenv=`; otherwise rootlesskit/dockerd exit with missing variables.
6. **AppArmor profile must be loaded before running the installer.** `ensureRootlesskitAppArmor` is called before `installRootlessDocker` so unprivileged user namespaces are allowed on Ubuntu 24.04+.
7. **`userdel` can race a slow dockerd shutdown.** `cleanupAgent` first `pkill -u -9`s lingering agent processes, then retries `userdel -rf` up to 20×500ms; force-destroy tolerates a final `userdel` failure so the teardown path itself never panics. Root-suite CI wraps runs with a `/etc/passwd` + `/etc/bunkerd/ssh` + `/run/bunker` snapshot to catch leaks (scripts/root-suite.sh).
8. **gvfsd-fuse mounts under `/run/user/<UID>` break spawn reset on desktop Ubuntu.** The user manager mounts a FUSE fs at `/run/user/<uid>/gvfs` (observed karaHermes-mde-7840hs, Ubuntu 26.04/GNOME, 40+ zombie mounts from prior test agents); it blocks `rm -rf` ("Device or resource busy") and recursive chown ("Permission denied" — no allow_other denies even root). `removeMountsUnder()` lazy-unmounts before the reset — and that reset now runs ONLY when `classifyRuntimeDir` says the state is actually stale — while the runtime-dir chown is non-recursive so it never descends into the mount (2ed1054).
9. **`TMPDIR` alone is not `/tmp` isolation.** A per-agent `TMPDIR` directory only redirects tools that honour it; anything writing the literal path `/tmp/...` shares the host directory with root and with every other agent. GAP-075 therefore makes `/tmp` itself private (pam_namespace per session, `PrivateTmp=yes` per unit) and points `TMPDIR` at it. Do not "restore" the old per-agent `TMPDIR` — the alternative was never a boundary.
10. **A failed scratch mount must not leave a mountpoint behind.** `EnsureAgentScratch` creates the mountpoint, mounts the size-capped tmpfs, and on failure REMOVES the mountpoint before returning the error: a group-writable directory without the tmpfs would be an unbounded cross-agent write surface (fail-closed). Tests pin that: a failed mount leaves no directory and no ownership change.
11. **RLIMIT_FSIZE (config default_disk_bytes) crash-loops .NET apps.** Prowlarr/Radarr ftruncate a 2TiB sparse file at first boot -> EFBIG -> SIGXFSZ. Configs should set default_disk_bytes: 0 (2ed1054; documented in the bunker-agent-isolation skill).
12. **A failed `systemctl --user disable` in `Destroy` step 2 is usually NOISE, not a destroy failure (DF-BUNKER-5).** The per-agent unit is the agent's `systemd-run --user` TRANSIENT unit, so from the root bunkerd (no user session bus) the call always exits non-zero while the destroy itself fully succeeds — user, SSH key and port range are all reclaimed. Observed live wordings: `Failed to connect to user scope bus via local transport: $DBUS_SESSION_BUS_ADDRESS and $XDG_RUNTIME_DIR not defined (consider using --machine=<user>@.host --user ...)` (service context), `Failed to connect to bus: No medium found`, and `Unit file bunker-docker-<id>.service does not exist.` (daemon started from a login session, which DOES have a bus). `noUserManagerFailure` / `unitAbsenceFailure` classify those three classes as non-actionable and log at Debug with the raw output; genuine failures (permission denied, unrecognised output) still Warn. ⚠️ Lesson from the first attempt: the classifier needles were written against a hand-written PARAPHRASE of the message, so every unit test and the Tier 2 judge passed while the live daemon still emitted the warning — tests over tool output must embed VERBATIM captured text (all observed variants), and only a live probe can falsify a paraphrased fixture. Reproduce with: start a scratch `bunkerd -c <cfg>` with `env -u XDG_RUNTIME_DIR -u DBUS_SESSION_BUS_ADDRESS`, spawn an agent, destroy it, and grep the daemon log for `systemctl disable failed`.
13. **A handler that mutates external state under the request deadline must run its COMPENSATING actions on a DETACHED context (INT-CI-005, 94f828b).** The 300s chi `middleware.Timeout` cancels the request ctx on spawn overrun; `exec.CommandContext(ctx, ...)` on that ctx NEVER runs the command, so a rollback borrowing the request ctx no-op'd and left a half-created agent (Linux user present, no `/etc/bunkerd/ssh/<id>` key, no registry row). Spawn's cleanup therefore runs under `rollbackContext` (`context.WithoutCancel` + 60s timeout, `spawn_failure.go`). If you add a new compensating action anywhere, run it on a detached, self-bounded ctx — never on the request ctx. Note `removeUserSliceLimits` now returns an error so the rollback can record it (destroy callers ignore it). A timed-out spawn's error names the stage and the request timeout (`spawn <id> failed at stage <stage>: spawn was cancelled by the server request timeout (request_timeout, default 300s): <cause>`), and the failure is journaled to `/var/lib/bunkerd/spawn-failures.jsonl` — read that file first when a spawn fails under load.
14. **A destructive preamble that cannot prove its precondition is a bug, not a precaution (INT-CI-008).** `installRootlessDocker` used to `systemctl stop user@<uid>.service` + `loginctl terminate-user <uid>` + `removeMountsUnder` + `rm -rf /run/user/<uid>` on EVERY install, "in case" the uid was recycled — and then started the manager, which on systemd 255 can never become active without that very directory. So the preamble both destroyed state a brand-new uid had nothing to do with AND created the failure it was meant to prevent. Structure it as `classifyRuntimeDir` (a probe of the OBSERVED state: owner, type, readability) → reset only on proven staleness → create + VERIFY → start. Keep the classifier's failure direction SAFE (unknown ⇒ treat as stale) so the historical protection is never silently dropped, and never let the ordering depend on a side effect of `enable-linger`, which is idempotent and takes no start action when lingering is already recorded.
15. **Orphan ownership must be PROVEN by a marker, never INFERRED from ports (DF-BUNKER-18).** The port-disjointness test only classifies an orphan whose persisted range lies entirely OUTSIDE this daemon's pool; a second daemon with an OVERLAPPING pool, or one whose port metadata is missing/unreadable, defeats it — and both shapes end in destroying another daemon's running agents. The marker (`<home>/.bunker/owner`, written at spawn, carrying this daemon's restart-stable `instance` id) is checked FIRST and independently of the range. Three rules go with it: the identity file must be created ONCE and never regenerated (a fresh id per restart reclassifies your OWN agents as foreign and leaks them forever); an unavailable identity must DISABLE the check and degrade to the legacy behaviour (never fail closed into destroying more, never fail daemon start); and the informational pool fingerprint inside the marker must stay OUT of the decision, or a legitimate pool-geometry change reclassifies your own agents as foreign.
16. **The systemd job Result does not name the cause — attribute failures from the journal (INT-CI-008).** `user-manager-start failed: unit user@1002.service: is-active=failed` hid the real reason (`pam_systemd`: "Failed to stat() runtime directory '/run/user/1002'" → "Not setting XDG_RUNTIME_DIR"), which is why the regression took a journal read to diagnose. `fetchUserManagerJournal` now captures a bounded excerpt into both the terminal error and the WARN, detached from the caller's deadline (`context.WithoutCancel`) so attribution still works after the client gave up, and assembled with `errors.New` so arbitrary host output is never interpreted as a format string.
